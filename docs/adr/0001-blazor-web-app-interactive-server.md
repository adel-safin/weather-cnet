# ADR 0001. Blazor Web App с InteractiveServer в одном хосте с API

Статус: принято

## Контекст

Задание требует бекенд и интерфейс на Blazor. Варианты: Blazor Server, Blazor WebAssembly с отдельным API, Blazor Web App с выбором режима рендера.

## Решение

Blazor Web App (.NET 10). Страница погоды помечена `@rendermode InteractiveServer`, остальное остаётся статическим SSR. Minimal API живёт в том же хосте.

## Причины

- WebAssembly потребовал бы отдельного клиентского проекта, CORS и повторной реализации моделей на клиенте — лишняя сложность для одного экрана.
- InteractiveServer даёт мгновенную первую отрисовку и обработку клика «Повторить» без ручного HTTP-слоя в UI: страница обращается к `ISender` напрямую.
- Ключ провайдера остаётся на сервере. В WebAssembly пришлось бы либо проксировать запросы, либо светить ключ в браузере.
- Один хост — одна команда запуска для проверяющего и один образ для развёртывания.

## Последствия

- Нужен постоянный SignalR-канал; при обрыве соединения Blazor показывает штатный оверлей переподключения.
- Предварительный рендер вызывает `OnInitializedAsync` дважды. Решается атрибутом `[PersistentState]`, иначе на каждое открытие страницы уходило бы два запроса к провайдеру.
- Публичный HTTP API не обязателен для работы UI, но оставлен: он документирует контракт, проверяется интеграционными тестами и пригодится другому клиенту.
