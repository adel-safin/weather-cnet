# ADR 0002. Result<T> вместо исключений для ожидаемых сбоев

Статус: принято

## Контекст

Внешний провайдер регулярно отвечает не-успехом: неверный ключ, неизвестная локация, исчерпанный лимит, недоступность. Это ожидаемые исходы, а не программные ошибки.

## Решение

Порт `IWeatherProvider` и обработчики возвращают `Result<T>` с типизированной ошибкой (`Error` + `ErrorType`). Исключения остаются для непредвиденного: их ловит `GlobalExceptionHandler` и превращает в `ProblemDetails`.

## Причины

- Сигнатура метода честно сообщает, что вызов может не удаться, — компилятор напоминает обработать оба исхода.
- Исключения на happy path дороги и зашумляют логи и телеметрию: 429 от провайдера — нормальная рабочая ситуация.
- Категория ошибки (`ErrorType`) один раз отображается в HTTP-статус в `ErrorResults`, поэтому новая ошибка не требует правок в эндпоинтах.
- UI получает готовое человеческое сообщение и показывает его вместе с кнопкой повтора.

## Последствия

- Немного больше кода: каждый вызов проверяет `IsSuccess`.
- `HybridCache` не умеет кэшировать «неуспех», поэтому в декораторе ошибка временно превращается во внутреннее исключение `WeatherProviderException` — так неудачный ответ не попадает в кэш. Исключение не покидает пределы слоя инфраструктуры.
