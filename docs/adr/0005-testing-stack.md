# ADR 0005. Тестовый стек: xUnit v2, WireMock.Net, bUnit, NetArchTest

Статус: принято

## Контекст

Требование задания — тесты. Нужен стек, который проверяющий запустит одной командой `dotnet test` на чистой машине.

## Решение

xUnit v2 + `Microsoft.NET.Test.Sdk` (VSTest), NSubstitute, Shouldly, `FakeTimeProvider`, WireMock.Net для HTTP, bUnit для компонентов, NetArchTest для правил архитектуры.

## Причины

- Изначально был взят xUnit v3 с Microsoft.Testing.Platform. В .NET 10 SDK на момент разработки `dotnet test` запускал тестовый хост, но получал пустой список тестов: прямой запуск бинарника работал, через SDK — нет. Проверяющий увидел бы «выполнено 0 тестов», поэтому выбран классический стек, который работает предсказуемо.
- WireMock.Net позволяет проверять реальные сценарии HTTP: коды ошибок провайдера, повторы, сценарий «первая попытка упала, вторая удалась». Подмена `HttpMessageHandler` заглушкой такого не даёт.
- Фикстуры — настоящие ответы weatherapi.com, сохранённые в файлы. Так тесты ловят особенности формата: время без смещения, protocol-relative адреса иконок, структуру `error`.
- bUnit проверяет три состояния экрана из задания (загрузка, ошибка с повтором, данные) на уровне разметки, без браузера.
- NetArchTest превращает договорённость о направлении зависимостей в падающий тест. Правила дополнительно проверяют, что набор типов под правилом не пуст: иначе такое правило проходило бы вхолостую.

## Последствия

- Недоступны удобства xUnit v3 (`TestContext.Current.CancellationToken`, встроенный MTP-раннер). Переход на v3 — вопрос обновления двух пакетов, когда связка SDK и платформы стабилизируется.
- Интеграционные тесты поднимают полное приложение на каждый класс тестов; при росте их числа стоит перейти на общую фикстуру коллекции.
